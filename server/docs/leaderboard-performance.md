# 排行榜模拟数据性能验证

验证日期：2026-11-14。本机 Node.js 25、Docker PostgreSQL 16 的空白隔离数据库；未在生产数据库压测。

原版代码直接从 Git 提交 `d138f7b8c8126fe9d3410df5cfc3a3da7aacb5fb` 加载，优化版使用当前源码。双方读取相同配置、相同真实数据，按交错顺序调用。每种用户规模的六种榜单，各采集原版 200 次、优化版 200 次，共 7200 次；表内时间单位为毫秒，含原有两次数据库访问，缓存已预热。

这批请求的模拟名单分别为学力 1629 人、时长 790 人、词汇 1662 人；另对恰好 2100 人的最大名单单独验证，首次生成加计分耗时 5.849ms，10 万次热缓存命中加二分查找平均每次 0.000543ms。

P50 最大增量为 0.209ms，P95 最大增量为 2.211ms，未发现明显、持续的访问性能回退。固定限额的内存缓存、没有额外数据库请求/写入以及不把模拟名单传给数据库，是控制开销的主要措施。每日首次生成、真实分数区间变化仍存在一次性计算成本，不能把本机结果表述为生产环境绝对零开销。

复现时，在已建好表结构的本机空白隔离数据库中运行：

```sh
cd server
LEADERBOARD_BASELINE_REF=d138f7b8c8126fe9d3410df5cfc3a3da7aacb5fb \
DATABASE_URL='postgres://gotit:gotit_test@127.0.0.1:55436/gotit_leaderboard' \
./node_modules/.bin/tsx src/lib/leaderboard-simulation.performance.ts
```

脚本只允许本机端口 55436、数据库 `gotit_leaderboard`，要求初始用户表为空；只删除脚本自身创建的测试账号，并还原榜单配置。
